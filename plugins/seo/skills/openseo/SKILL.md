# OpenSEO

[every-app/open-seo](https://github.com/every-app/open-seo) (MIT) is a web app plus an MCP server. The SEO data comes from **DataForSEO**, which is paid per request. The app is free; the data is not.

## Hosted or self-hosted?

- **Self-hosted (default for Dean):** free app, and DataForSEO bills Dean's own key directly.
- **Hosted (openseo.so):** $10/month plus a 28% markup on every DataForSEO request. Only worth it if Dean doesn't want to run Docker or Cloudflare.
- Either way, tell Dean roughly what a research run will cost in DataForSEO credits before big jobs (large keyword lists, full-site audits, many rank checks).

## Set up (once)

Prefer Docker on Dean's machine or server. Follow the repo's `docs/SELF_HOSTING_DOCKER.md`:
1. Clone the repo, then `export COMPOSE_FILE=deploy/standalone/compose.yaml`.
2. In `deploy/standalone/.env`: set `STORAGE_SECRET_KEY` (`openssl rand -hex 32`) and `DATAFORSEO_API_KEY` (Dean enters it; never echo it).
3. `docker compose pull && docker compose up -d`, and wait for `OpenSEO initialized and ready.` in `docker compose logs -f init`.
4. Open http://localhost:3001 and create the admin account **before** exposing it anywhere (registration closes after the first account).
5. Putting it online: set `BETTER_AUTH_URL` to the HTTPS domain and put a reverse proxy in front of `127.0.0.1:3001`. Alternatively, the Cloudflare deploy (`docs/SELF_HOSTING_CLOUDFLARE.md`) needs no server and works on the free plan; put Cloudflare Access in front of it.

Needs Docker with at least 4 GiB of memory. Update with `docker compose pull && docker compose up -d`.

## Connect Claude Code

- Add the self-hosted MCP server: `claude mcp add --transport http openseo <instance-url>/mcp` (use `--scope user` to have it in every project). Sign in with the OpenSEO account, or use an API key from OpenSEO Settings.
- OpenSEO's 12 workflow skills (keyword research, clustering, SEO audit, competitor analysis, competitive landscape, link prospecting, local SEO, AI visibility, AI prompt research, project setup, coach, report) come from their own marketplace, so they stay up to date:
  ```
  /plugin marketplace add every-app/open-seo
  /plugin install openseo@openseo
  ```
  Their plugin's built-in MCP server points at the **hosted** service (`app.openseo.so/mcp`). When self-hosting, don't sign in to that one. In `/mcp`, check that the self-hosted server is the one connected, so Dean isn't billed through the hosted markup.
- Their reports add a "Generated by the OpenSEO … skill" link. Remove it from reports delivered to clients unless Dean wants it.

## Using it well

- Start with **seo-project-setup** for each site (scope, goals, competitors, key pages) so later runs share context.
- Typical flow for a new site: keyword research → clustering into pages → competitor gaps → content plan. For an existing site: SEO audit → fix list → rank tracking on target terms.
- Hand findings to the build: page titles and meta, the heading structure, internal links and schema go straight into the site's code (see the web-design skills for layout).
- Connect Google Search Console in OpenSEO when Dean owns the site. Real click and impression data beats estimates.
- Treat volumes and difficulty scores as estimates, and say so in reports.

## Don't

- Don't run large paid jobs without Dean's go-ahead.
- Don't expose a `local_noauth` instance to the internet.
- Don't scrape or crawl sites in ways that break their terms. Crawls of private networks are blocked by design.
